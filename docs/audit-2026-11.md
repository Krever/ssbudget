checked by hand where marked. This file is the list of all findings, so that none is lost. Change the status of an item when you

"Checked" means that the claim was confirmed in the code or in the deployment by a second look, not only by the review pass.

- [x] **Password login had no attempt limit, and each attempt takes 64 MB.** Now: at most two Argon2 runs at a time, and a lock

- [x] **Dashboard "Edit Balances" lost a cent** (`(d * 100).toLong`: 19.99 became 19.98; checked) and wrote every manual account

  `F/pages/DashboardPage.scala`.
- [x] **Deletes ran on one click.** Category, account, rule, bank connection, card group, currency. Now a two-click button
  (`Loading.confirmActionButton`: the first click arms it for 4 seconds). Not yet: passkey delete (Settings).
- [x] **Test mode turned on when the variable only existed**, also with the value `false`, and with no warning. Now: only `1` or
  `true`; a warning at start; the app refuses to start in test mode when `SSBUDGET_RP_ID` is not `localhost`. `B/Main.scala`.
- [x] **Database import did not migrate and accepted any SQLite file.** Now: a file with no migration history is refused, a file

- [x] **"Total" under Bank Accounts on the Accounts page was the sum of all roles.** Now the spending total.
  `F/pages/AccountsPage.scala`.

  CLAUDE.md). `F/pages/TransactionsPage.scala`.
- [x] **Exchange rates refreshed only from a button in Settings.** Now each "sync all banks" fetches rates first; a failure is a
  warning on the job and does not stop the sync. `B/banking/ImportJobService.scala`.

## Security and operations

- [ ] **A session alone can export or replace the database and add or delete a passkey**, while an MCP token needs an identity
  proof. Session tokens are stored in plain text (`M/V2__auth_schema.sql`, `B/db/repository/SessionRepository.scala`), so a
  backup file holds working logins. Fix: store SHA-256 of the token (as `McpTokenService` does), leave `sessions` out of the
  export, ask for an `IdentityProof` on import, export, passkey register and passkey delete. M.
- [x] **No copy of the database before a migration.** Checked: fly.io keeps a daily volume snapshot for 5 days, so the data is
  not without backup; what is missing is a copy just before Flyway runs, and anything older than 5 days. Fix: in
  `docker/entrypoint.sh`, `sqlite3 .backup` to `/data/backups` before the app starts, keep the last N; think about an off-machine
  copy. S.
  Done: `docker/entrypoint.sh` copies the database to `/data/backups` before each start and keeps the newest 5. An off-machine copy is still open.
- [x] **No fly health check** (`fly.toml` has no `[[http_service.checks]]`; the Docker `HEALTHCHECK` is not read by fly). A deploy
  whose migration fails can look successful. Fix: a check on `/api/health` with a grace period for the JVM start. S.
  Done: a check on `/api/health` in `fly.toml`.
- [ ] **`/api/auth/setup` is open when no password hash exists, also when passkeys exist**, and accepts an empty password
  (`B/AuthRoutes.scala`, `setupPassword`). Matters on a fresh or restored instance. Fix: a one-time setup secret from the
  environment or the boot log, refuse when a passkey exists, a minimum length. S.
- [ ] **No CSRF or Origin check on cookie routes.** `SameSite=Lax` (batch 1) closes most of it. Still open: a middleware that
  refuses non-GET requests on `/api` and `/metabase` whose `Origin` is not an RP origin. S.
- [ ] **No security headers** (CSP, `nosniff`, `frame-ancestors`, `Referrer-Policy`) on the app's own responses. S.
- [ ] **No request size limit outside `/mcp`.** Fix: `EntityLimiter` of about 1 MB on the auth routes, a larger explicit limit on
  the import route. S.
- [ ] **One global pending WebAuthn challenge**, replaced by a public route (`B/auth/WebAuthnService.scala`). A stranger can make
  each passkey login fail. It is denial of service, not a bypass. Fix: key the pending challenges by a random id with an expiry. M.
- [ ] **Expired sessions are never deleted** (`SessionService.cleanupExpiredSessions` has no caller), a password change keeps all
  sessions, and there is no "sign out everywhere". `last_used_at` is written on every request. S.
- [ ] **Failures of background work go to stdout only** (`B/service/BudgetSnapshotTrigger.scala`, `B/Routes.scala`
  `freeMoneyHistory`). If the daily snapshot starts to fail, nothing shows it. Fix: keep the last success or error and show it on
  the Dashboard; log at ERROR level. M.
- [ ] **Metabase proxy does not renew the service session after a 401** (`B/analytics/MetabaseClient.scala`). "Explore" can stop
  working until a restart. S.
- [ ] **Container hardening.** The image runs as root; the Metabase jar is downloaded with no checksum; the local Enable Banking
  key and the backups in `~/Downloads` have mode 644. S.

Checked and sound: every data route needs a session; session and MCP tokens are 256-bit random; MCP tokens are hashed and never
logged; the Metabase proxy checks the app session first and is bound to loopback; static files cannot leave their directory; SQL
is parameterised; no secret is in git or its history; no CORS is configured.

## Refactor and make stricter

Backend:

- [ ] **Business logic in `Routes.scala`** (about 600 lines). Seams: period lifecycle and planned items (writes); period reports
  (`savingsPeriodBaselines`, `movedToInvestments`, `periodSummaries`); accounts; categories and rule import, export, reorder;
  transaction list; backup and restore. `Routes.make` and `ServerBuilder` each build a `BudgetSnapshotService`. Extract in this
  order: PeriodService, PeriodReportService, then accounts and categories. M.
- [ ] **Multi-step writes are not atomic**: each repository method commits by itself. `startNewPeriod`, `importRules` (its comment
  says "atomically"), `deleteCategory`, `deleteAccount`, `createAccount`, `CategorizationService.applyChange`,
  `BankingService.callback`. No unique index allows only one open period. Fix: repositories give `ConnectionIO`, services
  transact; `CREATE UNIQUE INDEX ... ON periods((1)) WHERE ended_at IS NULL`. M.
- [ ] **Two implementations of "balance at a past time".** `BalanceHistory.asOf` takes the last record at or before the instant
  and does not carry it forward through the ledger; `BudgetSnapshotService.balanceOf` does. With a sync some days before a period
  opens, the Periods page counts those days in the new period. Fix: one rule in `BalanceHistory`, used by both. M.
- [ ] **A missing exchange rate means 1:1, with no signal**, on the server (`BudgetQueries.primaryConverter`,
  `RateTable.convert`) and on the client. Rates have 4 decimals, truncated, which is too few for weak currencies. A change of the
  primary currency leaves old rates, snapshots and planned savings in the old one. The category history is converted at the latest
  rate in one service and at the rate of each month in the other. M.
- [ ] **The currency of an account or planned item can change after it has history** (`updateAccount`); readers ignore
  `balance_snapshots.currency`. Fix: refuse the change when there is a link or history. S.
- [ ] **Foreign keys are off** (`PRAGMA foreign_keys` is never set). Orphan `expense_records` exist. Before turning them on:
  `refreshRates` stores rates for about 30 currencies that are not in `currency_settings`. M.
- [ ] **The bank parser invents values**: an amount that does not parse becomes 0, a missing date becomes "now" (and makes a new
  dedup key on each import), a missing currency becomes PLN; pending entries count in every sum. Not verified that the connected
  banks send such entries. S to M.
- [ ] **A period boundary has three definitions**: `periodWindow` (midnight to midnight), the ledger terms (from the day after
  the start), `BalanceHistory.asOf` (the instant, or the end of the day before). Market result mixes two of them. Fix: one
  `PeriodWindow` value with named views. S to M.
- [ ] **Timestamps are text of varying width, compared as strings** (0, 3, 6 or 9 fraction digits). Wrong order only inside one
  second. Fix: one fixed format in `Meta[Instant]` and a migration that normalises the rows. S to M.
- [ ] **Query count and full loads.** About 250 statements for one Periods page; each snapshot pass loads all balance snapshots
  and all records; `setBalance` inserts a snapshot when nothing changed; the rule engine loads every transaction with `raw_json`
  on each start and each rule change; `markInternalTransfers` rewrites every row. M.
- [ ] **One string as the error model** (`Result = IO[Either[String, A]]`, defined twice; every error is the same status). The
  client cannot tell an expired session from a bad input. Fix: a small sealed `ApiError` with status codes. M.
- [ ] **Wide tuples and raw strings from repositories**; `Category` allows illegal combinations (budget type, bill payments,
  transfer account) that only `normalized` keeps apart. Fix: row case classes, an `EbAccountUid` type, the category kind as an
  ADT `Plain | Budget | Transfer`. M.
- [ ] **Enum columns have no CHECK**; one bad value fails a whole list read; `BankLinkTarget.fromParts` maps an unknown kind to
  `Unlinked` with no signal. S to M.
- [ ] **Wall-clock reads** (`Instant.now()` in routes and services; a spec built on `LocalDate.now`). Period rules cannot be
  tested at a chosen date. Fix: pass a clock. M.

## Facts to keep in mind

- The backend has no scheduler; the machine suspends, and snapshots run off page traffic. A function that must run with nobody in
  the app is not possible today.
- The single-connection SQLite pool serialises all work. That is correct for one household; a long transaction makes every other
  request wait.
